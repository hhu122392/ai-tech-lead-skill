# 集成与最终签字

## 1. 集成原则

- 主 Agent 决定是否采纳每个子 Agent 的代码。
- 一个任务一个任务地集成，避免一次性混合多个未知 Diff。
- 冲突必须按业务语义、接口契约和不变量解决，不得只选择“能编译”的一边。
- 子 Agent 无权自行合并到主分支或发布生产，除非明确授权。

## 2. 集成检查

每次集成后检查：

- 修改是否仍在合同范围内
- 是否覆盖或删除用户已有修改
- 是否破坏其他任务接口
- 是否引入重复实现或互相矛盾的测试
- 配置、依赖、迁移是否完整
- 用户已有改动是否保持，任务前后 diff 是否可追溯
- 非 Git 项目是否能从快照恢复
- 若使用外部 Agent，调用前是否已通过 YOLO／免确认权限和最高 thinking 两项前置检查，并能找到对应证据

R2／R3 每个关键任务集成后可运行定向测试；全部集成后必须再运行最终验证集。

## 3. 最终验收矩阵

逐条填写：

| 验收项 | 实现证据 | 测试／运行证据 | 结果 | 备注 |
|---|---|---|---|---|

找不到实现证据或验证证据的条目，不得标记通过。

## 4. 完成状态

子任务状态与最终状态不是一回事：`DONE` 只能说明执行者提交了交付，`INTEGRATED` 说明代码已进入最终工作区；只有主 Agent完成最终验证后，才能转换为以下三种最终状态。

### VERIFIED COMPLETE

满足：

- 验收标准全部通过
- 主 Agent 检查最终 Diff
- 必要测试在最终工作区由主 Agent 重跑
- 重大审查问题已解决
- 未留下未披露风险
- 所有 R3 审批和高风险操作均有证据

### IMPLEMENTED, NOT FULLY VERIFIED

代码已实现，但真实环境、外部服务、设备、生产数据、完整 E2E 或其他关键验证不可用。必须列出未验证项和风险。

### BLOCKED

需求、环境、权限、依赖或风险导致无法完成。保留已获得的证据，明确下一步，不伪装完成。

## 5. 最终报告

使用 `../assets/FINAL_SIGNOFF_TEMPLATE.md`。至少包含：

- 完成状态
- 用户可观察的结果
- 主要代码变更
- 验收矩阵摘要
- 主 Agent 亲自运行的验证命令和结果
- 审查结论
- 未验证项与残余风险
- 回滚方法
- R3 审批和任务生命周期记录
- 外部 Agent 前置检查记录（Provider、权限／YOLO 证据、最高／生效 thinking 证据）

## 6. 最终责任

主 Agent 不得写：

```text
子 Agent 说测试通过，所以已完成。
```

应写：

```text
我已检查最终 Diff，并在集成状态运行了以下验证……
```

若没有做到，就诚实标记未完全验收。
