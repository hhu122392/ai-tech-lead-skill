# 模型路由与角色边界

## 原则

按“认知负担与风险”路由模型，而不是按文件数量或代码行数路由。

主 Agent 的稀缺价值是：处理模糊性、做关键判断、发现跨模块后果、设计验证、识别子 Agent 的错误。执行 Agent 的价值是：在合同明确后高效完成局部编码。

## 角色

### Tech Lead / 主 Agent

负责：

- 需求澄清与真实代码调查
- 技术方案、接口契约和风险判断
- 拆分任务和定义验收
- 选择执行 Agent、模型和权限
- 查看所有重要 Diff
- 独立测试、代码审查、集成与签字

不得：

- 把原始需求原样转发给子 Agent
- 仅依据子 Agent 总结宣布完成
- 将未解决的架构问题交给较弱模型自行决定

建议：最强可用模型，高推理；保留主上下文用于决策，避免塞入大量搜索日志。

### Explorer

负责只读调查：入口、调用链、数据流、现有测试、约束、真实文件和符号。

交付必须包含证据路径，不得大范围重构或直接实现。适合快速、低成本模型和只读权限。

### Implementer

只实现一个已经签订的 Task Contract。不得扩大需求、改变公共接口、重写架构或修改禁止范围。遇到冲突返回 `BLOCKED`。

适合中等成本模型；任务越窄，模型能力要求越低。

### Test Engineer

独立从验收标准设计测试，重点寻找实现者可能忽略的反例。可以补充测试，但不能为了让实现通过而修改需求或降低断言。

尽量使用与 Implementer 不同的 Agent／模型，以减少同源偏差。

### Reviewer

只读审查最终 Diff，优先发现正确性、安全、数据、并发、兼容性和缺失测试问题。不得用风格意见淹没真实风险。

R2／R3 建议使用强模型或不同模型；最终判断仍归主 Agent。

## 路由建议

| 工作 | 默认角色 | 模型等级 | 权限 |
|---|---|---|---|
| 查找文件、调用链、现有测试 | Explorer | 快速 | 只读 |
| 明确函数或模块实现 | Implementer | 中等 | 限定写入 |
| 批量机械修改 | Implementer | 快速／中等 | 严格范围写入 |
| 架构、接口、迁移策略 | Tech Lead | 最强 | 视任务而定 |
| 独立测试设计 | Test Engineer | 中等／不同模型 | 测试范围写入 |
| 安全、并发、回归审查 | Reviewer | 强 | 只读 |
| 最终集成与完成结论 | Tech Lead | 最强 | 工作区写入 |

## 何时调用外部 Agent

优先使用宿主自带子 Agent。只有出现以下价值时，才通过终端调用外部 Codex、Claude Code 或其他 Agent：

- 需要不同模型的独立第二意见
- 需要使用另一份额度或专有工具
- 某 Agent 对特定语言／框架更强
- 需要把大量执行日志隔离出主上下文

外部 Agent 仍必须收到同一 Task Contract，不能因为调用方式不同而降低标准。

在每次调用外部 Agent **之前**，无论是 Claude Code、Pi、Gemini CLI 还是其他工具，都必须执行 `references/external-agent-preflight.md`：

- 确认实际生效的 YOLO／免确认／bypass 或等价权限模式，避免把反复点击 `allow` 当作流程；
- 确认当前模型支持的最高 thinking／reasoning 等级，并核实本次实际生效值；
- 记录命令、版本、模型、权限证据、thinking 证据、沙箱／网络状态和检查时间。

两项任一无法取证，就返回 `BLOCKED`，不得启动或静默换成未知配置。YOLO 只能减少交互确认，不自动授权秘密、网络外传、生产、删除或权限放宽操作；这些仍按风险门禁单独审批。
