# Task Contract 标准

## 目的

执行 Agent 能力较弱时，质量主要取决于主 Agent 是否消除了任务中的模糊性。Task Contract 是主 Agent 与执行 Agent 之间的工程合同，不是聊天提示词。

使用 `../assets/TASK_CONTRACT_TEMPLATE.md`。

## 必填字段

### 1. 身份与单一目标

写清任务编号、执行角色和一个主要交付结果。不要用“优化”“完善”“顺便”等开放词。

### 2. 背景与事实来源

只提供经过主 Agent 验证的事实：真实文件、符号、调用链、错误表现、接口和已有测试。不要把整段原始聊天记录塞给执行者。

### 3. 当前行为与目标行为

分别描述，避免执行者误把重构当需求。

### 4. 非目标

明确本任务不解决什么，防止顺手扩大范围。

### 5. 写入边界

列出：

- 允许修改的文件／目录／符号
- 禁止修改的文件／公共接口／数据结构
- 唯一文件所有权
- worktree／分支／基线 commit

### 6. 不变量与接口契约

说明必须保持的行为，例如：

- API 响应字段不变
- 数据库旧数据兼容
- 错误码格式不变
- 权限边界不变
- 性能上限不退化

### 7. 已决定的实现约束

执行 Agent 不应重新决定架构。主 Agent 应写清：原子性、事务、幂等、重试、依赖限制、框架模式、日志与错误处理等。

### 8. 验收标准

每条标准要可执行。优先 Given／When／Then，覆盖：

- 正常路径
- 错误路径
- 边界值
- 与本次风险相关的并发、安全或兼容性

### 9. 验证命令

写出执行者必须运行的定向命令，但明确：执行者的结果仍需主 Agent 重跑。

### 10. 停止并上报条件

至少包含：

- 代码事实与合同矛盾
- 需要修改禁止范围
- 基线测试已失败且无法与本次影响隔离
- 必须改变公共接口
- 缺少依赖、凭证或环境
- 出现新的架构／安全决策
- 外部 Agent 的实际 YOLO／免确认权限或最高／生效 thinking 无法取证

出现时返回 `BLOCKED`，不得猜测。

合同还必须写明：

- 基线状态、用户已有改动和快照位置；非 Git 项目使用的恢复快照。
- 任务尝试编号、Agent／模型、超时上限和允许的重试次数。
- R3 操作的人工批准人、批准范围、批准时间和证据位置。
- 发生中断、崩溃或越界修改时的回滚动作。
- 若调用外部 Agent，补充 Provider／版本、脱敏启动命令、权限证据、最高／生效 thinking 证据和检查时间。

### 11. 交付格式

必须返回结构化证据，使用 `../assets/SUBAGENT_DELIVERY_TEMPLATE.md`。

## 合同质量自检

派工前主 Agent 应能回答：

- 执行者不看父会话，是否仍能理解？
- 执行者能否知道什么绝对不能改？
- 执行者遇到意外时是否知道停止？
- 主 Agent 能否在不相信其自评的情况下独立验收？
- 任务失败能否安全回滚？

任一答案为“否”，合同尚未完成。
