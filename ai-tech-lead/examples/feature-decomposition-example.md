# 示例：主 Agent 如何拆分一个多文件功能

需求：为后台增加“导出用户 CSV”，支持筛选、权限控制和审计日志。

## 不合格拆法

```text
Agent A：做后端导出。
Agent B：做前端按钮。
Agent C：补测试。
```

问题：接口未固定、权限和审计不明确，前后端会各自猜测；测试 Agent 也不知道正确行为。

## 合格拆法

### 主 Agent 先保留的决策

- 导出权限：仅 `user.export`
- API：`POST /admin/users/export`
- 请求 Schema、错误码、文件名和编码
- 最大行数、异步／同步策略
- 审计事件字段
- 验收矩阵和风险 R2

### T1：后端导出实现

- 唯一所有权：API、service、CSV serializer
- 不允许改权限模型
- 验收：筛选正确、行数上限、CSV 转义、错误码

### T2：权限与审计集成

- 在 T1 接口契约固定后执行
- 唯一所有权：permission guard、audit event
- 验收：无权限拒绝；成功和失败均有规定审计记录

### T3：前端入口

- 依赖固定 API Schema
- 唯一所有权：页面、按钮、下载状态
- 验收：权限可见性、加载、成功下载、错误展示

### T4：独立测试

- 不读取实现者自评
- 从验收矩阵设计边界、权限、转义、超限和失败用例

### T5：只读审查

- 审查最终集成 Diff
- 重点：越权、CSV 注入、内存峰值、敏感字段和审计缺口

### 主 Agent 最终工作

- 逐任务集成
- 检查接口一致性
- 运行类型检查、后端单元／集成、前端测试和真实下载验证
- 填写验收矩阵并签字
